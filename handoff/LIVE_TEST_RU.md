# Живая проверка оплаты, бота и доступа (v1.1)

Этот файл для владельца. Каждый пункт: **что сделать → что должно произойти → что проверить в админке**.
Ставьте галочку только после того, как сами увидели результат. Что уже проверено автотестами (`npm test`), отмечено отдельно: автотест проверяет логику, но не настоящий сервер провайдера.

Перед началом:
- Откройте бота @vibentry_bot → «Открыть Vibentry» → «Админка» → вкладка **Система**. Нажмите «Проверить ещё раз». Все строки, кроме ещё не подключённых провайдеров, должны быть зелёными. Если какая-то строка красная, сначала исправьте причину, которая там написана.
- Для теста нужен второй аккаунт Telegram (не админ): админ видит всё и без оплаты, поэтому на нём платёж не проверить. Дальше он называется «тестовый аккаунт».
- Ключи провайдеров добавляйте только в Cloudflare: Workers & Pages → `vibentry` → Settings → Variables and Secrets, тип **Secret**. В чат ключи не присылайте.

## 2. Telegram Stars: оплата, `successful_payment`, возврат

Stars работают без ключей, но только когда задана цена в звёздах: «Админка» → «Акции» → «Цена и общая скидка» → поле цены в Stars. Сейчас задана только цена в рублях (1299 ₽), так что сначала решите, сколько звёзд ставить. Платёж настоящий: звёзды спишутся, но в шаге 2.3 вы вернёте их кнопкой.

- [ ] **2.1 Сделать:** с тестового аккаунта (на нём должны быть звёзды) откройте «Тариф» → выберите Telegram Stars → «Оплатить …» → подтвердите оплату.
  **Должно быть:** Telegram показывает «Оплачено», в чате бота приходят два сообщения: «Оплата получена…» и письмо автора с планом на неделю. В приложении открываются урок 06+, промпты и База.
- [ ] **2.2 Админка:** «Участники» → тестовый аккаунт → тариф **Pro**, в «Платежах» строка `N ★`. «Обзор» → «Сейчас в продаже» и выручка выросли. «Система» → «Последняя оплата» показывает время этой оплаты.
- [ ] **2.3 Сделать:** в карточке участника нажмите **«Вернуть Stars»** → «Точно вернуть?».
  **Должно быть:** тост «Возврат проведён (1). Доступ закрыт.». Звёзды вернулись на тестовый аккаунт (Telegram пришлёт сервисное сообщение о возврате). Приложение после перезапуска снова показывает Free: урок 06 под замком.
  **Админка:** в карточке у платежа пометка «возврат», тариф Free. «Журнал» → «возврат Stars».
- [ ] **2.4 Возврат из Telegram без кнопки** (необязательно): если вернуть звёзды другим способом, Telegram присылает боту `refunded_payment`, и доступ тоже закрывается. Проверяется так же: карточка участника → «возврат».
- Автотест: `tests/admin.test.mjs` (`refundStarPayment` вызывается с нужным `charge_id`, доступ пропадает, повторный возврат отклоняется), `tests/core.test.mjs` (`successful_payment` с чужой суммой или валютой не открывает доступ, повтор того же апдейта не создаёт второй платёж).

## 4. CryptoBot — сначала testnet

- [ ] **4.1 Подготовка:** в @CryptoTestnetBot → Crypto Pay → Create App → скопируйте токен. В Cloudflare добавьте Secret `CRYPTOBOT_TOKEN` (тестовый токен) и переменную `CRYPTOBOT_API_BASE` = `https://testnet-pay.crypt.bot/api`. В @CryptoTestnetBot → ваше приложение → Webhooks → включите и укажите `https://vibentry.creator-desknalpaxstudio.workers.dev/api/webhooks/cryptobot`.
- [ ] **4.0 Цена:** криптой платят в USDT, поэтому нужна цена в USDT: «Акции» → «Цена и общая скидка» → «Цена в USDT». Без неё CryptoBot и xRocket не показываются покупателю. Сумму решаете вы.
- [ ] **4.2 Админка:** «Система» → «Проверить ещё раз» → строка «Криптовалюта (CryptoBot)» зелёная: «Ключи заданы, API отвечает». «Акции» → «Способы оплаты» → включите CryptoBot.
- [ ] **4.3 Сделать:** с тестового аккаунта «Тариф» → «Криптовалюта (CryptoBot)» → «Оплатить …» → оплатите тестовыми монетами (их выдаёт сам @CryptoTestnetBot).
  **Должно быть:** через несколько секунд в приложении «Оплата получена», доступ открыт, в чат бота пришло письмо автора.
  **Админка:** «Система» → «Вебхук Криптовалюта (CryptoBot)» стал зелёным со временем последнего вебхука. У участника платёж `сумма USDT · cryptobot`.
- [ ] **4.4 Повторный вебхук:** CryptoBot повторяет вебхук сам, если сервер не ответил. Нарочно повторить его из кабинета нельзя, поэтому проверьте последствия: в карточке участника **ровно один** платёж, в «Обзоре» выручка выросла один раз. Нажмите в окне оплаты «Я оплатил(а) — проверить» несколько раз: второго платежа не появится.
- [ ] **4.5 Чужой счёт / неверная сумма:** в @CryptoTestnetBot создайте счёт вручную (Crypto Pay → Invoices) на другую сумму и оплатите его. **Должно быть:** доступ никому не открылся, в «Участниках» новых Pro нет. Вебхук пришёл с верной подписью, но такого счёта у нас нет, и сервер его игнорирует.
- [ ] **4.6 Рабочий режим:** удалите переменную `CRYPTOBOT_API_BASE`, замените `CRYPTOBOT_TOKEN` на токен из основного @CryptoBot и зарегистрируйте тот же адрес вебхука там. Повторите 4.2. Первый настоящий платёж сделайте сами на минимальную сумму (можно временным промокодом).
- Автотест: `tests/payments.test.mjs` (подпись вебхука, неверная сумма и валюта отклоняются, повтор не даёт второго доступа, вебхук без подтверждения у провайдера доступ не открывает).

## 5. Platega (карта / СБП)

У Platega нет публичной тестовой сети, поэтому проверка — настоящим платежом на маленькую сумму.

- [ ] **5.1 Подготовка:** в Cloudflare добавьте Secrets `PLATEGA_MERCHANT_ID` и `PLATEGA_SECRET`. Если менеджер Platega назвал код метода оплаты (СБП, карта), добавьте его в `PLATEGA_PAYMENT_METHOD`. В кабинете Platega укажите callback-адрес `https://vibentry.creator-desknalpaxstudio.workers.dev/api/webhooks/platega`.
- [ ] **5.2 Админка:** «Система» → строка «Карта / СБП» зелёная: «Ключи заданы, API отвечает». Если там «у провайдера нет метода проверки соединения» — это нормально, проверка будет на шаге 5.3. Включите Platega в «Акции» → «Способы оплаты».
- [ ] **5.3 Сделать:** временно создайте промокод на большую скидку (например, −90%), оплатите с тестового аккаунта картой или через СБП.
  **Должно быть:** после оплаты страница Platega возвращает в приложение, через несколько секунд открывается доступ и приходит письмо автора.
  **Админка:** у участника платёж `сумма ₽ · platega`, «Вебхук Карта / СБП» зелёный, «Последняя оплата» обновилась.
- [ ] **5.4 Повтор:** как в 4.4 — в карточке ровно один платёж, повторное «Я оплатил(а) — проверить» второго не создаёт.
- [ ] **5.5 Возврат:** деньги возвращайте в кабинете Platega. Затем в карточке участника нажмите «Отозвать Pro», чтобы закрыть доступ (кнопка денег не двигает).
- [ ] Удалите временный промокод.
- Автотест: `tests/payments.test.mjs` (сумма и валюта сверяются с ответом Platega, а не с вебхуком).

## 6. xRocket

Адаптер переписан под текущий API xRocket Pay по их OpenAPI (https://pay.api.xrocket.exchange/api/docs-json): создание счёта `POST /api/v1/invoices` (`priceAmount`, `priceCurrency`, `numPayments`, `clientInvoiceId`), статус `GET /api/v1/invoice?invoiceId=…` (`status: paid`), вебхук с заголовками `Signature`, `Signature-Timestamp`, `Signature-Version: v1`. Живьём это **не проверено**, поэтому в админке у xRocket остаётся пометка «сначала проверьте на тестовом ключе» (`needsSandboxCheck`).

- [ ] **6.1 Подготовка:** в @xRocket → xRocket Pay → создайте приложение → API Token в Secret `XROCKET_API_KEY`. Там же включите вебхуки на адрес `https://vibentry.creator-desknalpaxstudio.workers.dev/api/webhooks/xrocket` и скопируйте секрет вебхука в Secret `XROCKET_WEBHOOK_SECRET`.
- [ ] **6.2 Админка:** «Система» → строка «Криптовалюта (xRocket)» зелёная. Если красная с кодом 401 — токен неверный, с кодом 404 — у xRocket снова поменялся адрес API, напишите мне текст ошибки.
- [ ] **6.3 Сделать:** включите xRocket и оплатите минимальную сумму (с временным промокодом) с тестового аккаунта.
  **Должно быть:** доступ открывается, «Вебхук xRocket» зелёный. Если оплата прошла, а доступ не открылся, нажмите «Я оплатил(а) — проверить». Если не помогло, пришлите мне время оплаты и текст из строки «Вебхук xRocket». Ключи не присылайте.
- [ ] **6.4** Только после успешной 6.3 скажите мне: я уберу `needsSandboxCheck` в `server/providers/xrocket.mjs`, и пометка исчезнет.
