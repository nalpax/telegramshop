# Vibentry — мини-апп и бот

> **Версия для GitHub: без платных текстов и исходных PDF.** Дизайн, бот, оплата, админка и первый бесплатный урок включены. Полный `data/lessons.json`, `data/resources.json` и `handoff/course/` намеренно исключены через `.gitignore`. Без них сервер запускает демо и первый урок, но не создаёт платёжных счетов за отсутствующий контент. Подключение авторского курса описано в [data/README.md](data/README.md). Упоминания полного импорта ниже описывают локальную сборку владельца после подключения его файлов.

Рабочий проект с дизайном на основе согласованного зелёно-молочного макета. Внутри — настоящий знак **ve.**, графика, 24 текстовых урока, библиотека промптов, база материалов, поиск, профиль, прогресс, экран обязательной подписки, оплата Telegram Stars и админка цены/скидки.

**Последние решения владельца важнее старых PDF и картинок:** первый урок бесплатно после подписки на публичный канал; уроки 02–24 и материалы — после **одной покупки навсегда**, строго для Telegram ID покупателя. Приглашения в резервный приватный канал НЕ выдаём. Ежемесячной подписки и автосписания в приложении нет.

## Что нового в v0.3 (28 октября 2026)

- **Все тексты интерфейса, бота и уроков — на «вы».** Уроки теперь берутся из проверенного пакета `Vibentry_MiniApp_Handoff` (редакция для Mini App), а не из старого PDF v0.2.
- **Читалка уроков с форматированием:** заголовки, списки, чек-листы, таблицы, картинки, блоки кода с кнопкой «Копировать» (`public/js/markdown.js`, весь текст экранируется, ссылки только `https`).
- **Библиотека из 300 промптов** (30 категорий, поиск, карточка с копированием). Названия видны после подписки, тексты — после покупки.
- **Раздел «База»:** инструменты и ресурсы, ниши и услуги, клиенты, заказы, кейсы (32 материала) и 8 шаблонов из уроков. Материал «Как пользоваться курсом» открыт всем.
- **Дизайн:** минимальный размер текста 11 px (раньше 7–9 px), заметные закрытые материалы, золотистый цвет только для цены и скидки, полноразмерные чипы категорий. Бренд, палитра и логотип сохранены.
- **Сервер:** короткий кэш проверки подписки (`MEMBERSHIP_CACHE_SECONDS`), понятный ответ 503 при сбое Telegram, сообщение покупателю, если платёж получен, но доступ не открылся.
- **Импорт:** `node scripts/import-package.mjs <папка-пакета>` создаёт приватные `data/*.json`. Платные файлы по-прежнему не попадают в Git.
- Подробный отчёт: [handoff/REVIEW_2026-10-28.md](handoff/REVIEW_2026-10-28.md).

## Посмотреть дизайн

Нужен **Node.js 24+**. Зависимостей npm нет; `npm install` и сборка не требуются.

```sh
npm start
```

Открой адрес локального сервера, напечатанный в терминале (обычно порт 3000). На стартовом экране нажми **«Посмотреть дизайн в демо-режиме»**. Демо появляется только при отсутствии BOT_TOKEN и NODE_ENV, отличном от production. Оно открывает первый урок и локальный прогресс; покупки и админка в нём недоступны. Демо не имитирует проверенную подписку или успешный платёж.

```sh
npm run dev   # сервер с перезапуском при изменении файлов
npm run check # синтаксис, ассеты, наличие бесплатного урока
npm test      # серверные тесты; без внешних платежей
```

В `handoff/screenshots/` — снимки **работающего интерфейса**, в `handoff/reference/approved-design.png` — последний согласованный визуальный ориентир. Это разные артефакты.

## Реальный Telegram

1. Создай бота через BotFather. Токен сохрани в локальном `.env` или секретах сервера. Не отправляй его в чат и не коммить.
2. Скопируй `.env.example` в `.env`. Заполни `BOT_TOKEN`, `APP_URL` (публичный HTTPS), `REQUIRED_CHANNEL_ID` (например, @username публичного канала), `REQUIRED_CHANNEL_URL` и свой числовой `ADMIN_IDS`.
3. Назначь бота администратором канала. `getChatMember` надёжно проверяет других пользователей, когда бот — администратор. Свой Telegram ID можно узнать командой `/id` после запуска бота, затем внести его в `ADMIN_IDS` и перезапустить сервер.
4. На сервере задай `NODE_ENV=production`. Запускай приложение за HTTPS reverse proxy. Для контейнера обычно нужен `HOST=0.0.0.0`; по умолчанию привязка безопасно локальная.
5. Запусти **два процесса** из одного каталога и с одной `DATABASE_PATH`: `npm start` и `npm run bot`. Должен работать один polling-процесс на токен. Бот не удаляет чужой webhook автоматически: при его наличии останавливается.
6. Бот устанавливает команды и кнопку меню с HTTPS-адресом приложения. При необходимости настрой Main Mini App у BotFather. Открой бота → `/start` → мини-апп.
7. Подпишись на выбранный канал → «Проверить подписку». Первый урок откроется после серверной проверки.
8. У владельца в меню появится пункт **«Админка»** (на телефоне — в нижней панели, на компьютере — в боковом меню). Вкладки:
   - **Обзор** — число участников, Free/Pro, выручка в Stars, график за 14 дней.
   - **Участники** — все, кто открывал приложение: поиск по имени, @username или ID, фильтр Free/Pro, карточка с платежами и прогрессом, кнопки «Выдать Pro» / «Отозвать Pro».
   - **Акции** — цена, общая скидка с датой окончания и **промокоды** (процент, лимит, срок).
   - **Доступ** — до 5 каналов и чатов, на которые нужно подписаться, чтобы получить бесплатный урок (нужны **все**). Кнопка «Проверить бота» убеждается, что бот там администратор. Переменные `REQUIRED_CHANNEL_ID/URL` — только запасной вариант, пока список пуст.
   - **Журнал** — кто и что менял.
   В профиле у каждого участника есть значок **Free** (зелёный) или **Pro** (красный, появляется после оплаты).

Публичный канал и цену владелец ещё не выбрал. Они специально не выдуманы. Пока они не настроены, реальный сценарий подписки/платежа не может быть завершён.

## Способы оплаты

Основной — Telegram Stars (Telegram требует их для цифровых товаров внутри Telegram). Дополнительно можно включить Platega (карта, СБП), CryptoBot и xRocket (USDT): ключи в `.env`, переключатель и цены в **Админка → Акции**. Платёж засчитывается только после проверки у самого провайдера. Подробности и порядок запуска: `handoff/LAUNCH_CHECKLIST_RU.md`.

## Защита материалов

Все тексты, кроме промптов, выдаются только оплатившим, с лимитом запросов, водяным знаком и невидимой меткой читателя. Утёкший фрагмент можно привязать к аккаунту: `npm run trace-leak < текст.txt`. Полностью запретить скриншот технически нельзя.

## Оплата и аккаунт

- Цифровой продукт оплачивается через **Telegram Stars, XTR**, без стороннего платёжного провайдера.
- Сервер создаёт `createInvoiceLink`. Цена берётся из текущего предложения в базе, а не из запроса браузера.
- Счёт привязан к проверенному `user.id`. Бот проверяет `pre_checkout_query`: владельца, валюту, сумму, payload и срок счёта.
- Право на курс выдаёт только `successful_payment` от Telegram. Клиентский callback `paid` не выдаёт доступ.
- `telegram_payment_charge_id` уникален: повторная доставка уведомления не создаёт вторую покупку.
- У разовой покупки нет срока истечения. Вход с другого Telegram ID не получает эту покупку. Использование одного и того же Telegram-аккаунта на нескольких устройствах разрешено самой моделью Telegram.
- Уведомление `refunded_payment` отзывает право соответствующего платежа. UI возврата денег пока не реализован; `/paysupport` ведёт к владельцу.
- Смена цены не меняет уже оплаченные покупки. Счёт хранит снимок суммы на момент создания и принимается до одного часа.
- Доступ к платным урокам и промптам проверяется на сервере; они отсутствуют в публичной сборке. Подписка на обязательный канал повторно проверяется при запросе материалов.

## Данные и структура

```text
public/                 Только публичные файлы интерфейса
  assets/               Настоящий логотип и сгенерированная иллюстрация
  js/app.js             Экраны, навигация, оплата, Telegram SDK
  js/markdown.js        Безопасный показ форматированного текста
  js/course.js          Только названия уроков и материалов, без платных текстов
  style.css             Зелёно-молочная дизайн-система и адаптивность
server/                 HTTP API, Telegram auth, SQLite, polling-бот
data/free-lessons.json  Урок 01 (бесплатный), можно хранить в Git
data/lessons.json       Все 24 урока, ТОЛЬКО сервер
data/resources.json     Тексты 8 шаблонов из уроков, ТОЛЬКО сервер
data/prompts.json       300 промптов, ТОЛЬКО сервер
data/articles.json      Материалы раздела «База», ТОЛЬКО сервер
var/                    База SQLite; создаётся при запуске, не входит в ZIP
tests/                  Проверки прав, счетов, скидок и доступа
scripts/                Проверки, импорт пакета (import-package.mjs), старый импорт PDF
handoff/                Промпт Claude, оригиналы курса, макет, скриншоты
```

В пакете владельца есть пять коротких бесплатных материалов, но по последней просьбе владельца приложение открывает бесплатно только урок **01** (см. вопрос в отчёте). Содержимое 24 уроков перенесено из PDF с восстановлением абзацев и заголовков. Два промпта дополнительно оформлены кодовыми блоками. Иллюстрации внутри PDF и внешние ссылки требуют дополнительной редакционной проверки перед публикацией; PDF лежит в handoff для сверки. Это не обещание нового, ещё не написанного контента.

В каталоге «Шаблоны» некоторые карточки ведут в соответствующие уроки, где находятся оригинальные шаблоны. Не все шаблоны превращены в отдельные скачиваемые файлы.

Не выставляй корень проекта как static hosting! HTTP-сервер раздаёт только `public/`. Папки `data/`, `handoff/`, `var/` и `.env` не должны быть публичными. Бэкап SQLite делай вместе с WAL или штатным SQLite backup; база нужна для сохранения пожизненных покупок.

## Что проверено и что ещё проверить

Проверены Node-тесты и Chromium на мобильных ширинах 320/390 и настольной 1280: загрузка экрана подписки, демо, настоящий первый урок, задание, прогресс, поиск, закрытые уроки и профиль. Платёжные API проверены с тестовым адаптером Telegram, без реальных денежных операций.

**Не проверены живым Telegram:** членство в реальном канале, настоящий счёт Stars, доставка `successful_payment`, покупки с двух аккаунтов и публичное HTTPS-размещение. Для этого нужны токен, канал, развёртывание и выбранная цена. Текущий проект не опубликован в Telegram.

До продаж: проверь политику обработки данных, условия продажи/возврата и контакт поддержки; выполни живой тест покупки, восстановления доступа после перезапуска и возврата. Важно дополнить автоматизацию эксплуатации: supervisor, бэкапы, мониторинг и ограничение частоты запросов на reverse proxy. Не называй эти шаги пройденными до выполнения.
